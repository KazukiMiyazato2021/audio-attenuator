# coreaudiod 再起動への対応

ドライバを再インストールすると `coreaudiod` が再起動し、**保持していた
`AudioObjectID` と `AudioDeviceIOProcID` がすべて無効になる**。

macOS が自発的に再起動することもあるため、実運用でも起きる。

## 検出が難しい理由

**IOProc は動き続ける。** 正しい周期で、正しい形のバッファで発火し続け、
リングバッファの滞留量も健全に見える。ただし中身が無音になる。

したがって「音声が流れなくなったか」を監視しても検出できない。

## 確実な検出方法

`coreaudiod` の再起動後、CoreAudio は**新しいオブジェクト ID を払い出す**
(実測で 89 → 87 のように変化)。

デバイス UID から ID を再解決し、パイプラインを構築したときの ID と比較すれば
確実に判定できる。

`kAudioHardwarePropertyDevices` の変化を監視し、変化があったら上記を確認して
必要なら再構築する。

## リトライが必要

デバイスは `coreaudiod` の復帰よりわずかに遅れて再登録される。
最初の再構築試行が「出力デバイスが見つからない」で失敗することがあるため、
リトライを入れておく。

実測では1回目が失敗し、2回目のデバイス変化イベントで成功していた。
リトライが無いと、無関係なデバイス変化が起きるまで無音のまま放置される。

## 検証手順

```bash
sudo killall coreaudiod
```

を実行し、**手動でエージェントを再起動せずに**音が戻るかを確認する。

このとき、再起動前から再生していたアプリ自身も影響を受けて停止している
場合があるため、復帰確認は新しく音を鳴らして行うこと。
