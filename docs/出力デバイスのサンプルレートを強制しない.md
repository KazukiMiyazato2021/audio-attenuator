# 出力デバイスのサンプルレートを強制しない

パイプラインを 48kHz 固定にしていたため、「出力デバイスも 48kHz に設定すれば
変換が不要になって効率的」と考えて
`kAudioDevicePropertyNominalSampleRate` を 48000 に強制していた。

**これが Bluetooth で音程が下がる原因だった。**

## 何が起きるか

Bluetooth ヘッドセットは 48000 への設定を**受け入れる**(`status 0` を返し、
読み戻しても 48000 になる)。しかし A2DP リンクの実体は 44.1kHz のまま動き続ける。

結果、再生が約 8.8% 遅くなる。

```
44100 / 48000 = 0.919  →  約 1.5 半音下がる
```

人の声なら明確に低く聞こえる。**エラーはどこにも出ない。**

## なぜ見逃したか

内蔵スピーカーは本当に 48000Hz に対応しているため、この強制設定が無害だった。
48kHz 非対応のデバイスを試すまで表面化しない。
→ [[オーディオ検証の落とし穴]]

## 対処

デバイスは**そのデバイス本来のレートのまま**にして、変換は
[[HAL Output AudioUnit]] に任せる。

この「最適化」は自己矛盾していた。変換を避けるために入れた処理が、
**必要な変換の発生を自ら阻止していた**。

## 切り分け方

各経路の実測フレームレートをログに出すと、耳で気づく前に数値で分かる。

```
[mixer] levels: ... | Hz fb=48005 tap=0 out=47984
```

48000 から外れている経路が原因箇所。

デバイスが申告するレートと実際の挙動が食い違う場合があるため、
`kAudioDevicePropertyAvailableNominalSampleRates` で対応レートを確認しておくとよい。
実例: RY-WH02 は `16000` と `48000` のみを申告するが、本来のレートは 44100 だった。
