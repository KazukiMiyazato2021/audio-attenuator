# オーディオプロセスのグループ化

`kAudioProcessPropertyBundleID` をそのままアプリの identity として使うと破綻する。

## 問題

ブラウザは**ヘルパープロセス**で音を鳴らし、それらは全て同じバンドル ID を持つ。

```
com.google.Chrome.helper   pid=64006
com.google.Chrome.helper   pid=64007
```

バンドル ID でグループ化すると、無関係な Web アプリと通常のタブが同じ行にまとまる。
**片方の音量を変えると、もう片方も変わる。**

表示名も「Google Chrome Helper (Aperitif)」のようなヘルパーの実行ファイル名になり、
何のアプリか分からない。

## 対処

プロセスツリーを遡り、**macOS が「アプリケーション」として扱う最も近い祖先**を
identity にする。`NSRunningApplication(processIdentifier:)` が
`localizedName` を返す pid まで、`sysctl(KERN_PROC_PID)` で親を辿る。

```
pid=64006 (Chrome helper) → Google Chrome Beta   [com.google.Chrome.beta]
pid=64007 (Chrome helper) → Google Chrome Helper (Aperitif) [com.google.Chrome.helper]
```

Web アプリは**自分自身がアプリケーションとして登録されている**ため、
通常のタブと正しく分離される。

副次的に、表示名がローカライズされた正式名になる(「コントロールセンター」
「サウンド（システム設定）」など)。

## 限界

Chrome の Web アプリは macOS/Chrome が報告する名前が
「Google Chrome Helper (Aperitif)」であり、「YouTube」のような本来の名前には
できなかった。別アプリとして分離はできる。

## タップは全プロセスをまとめて

1つの `CATapDescription` は複数のプロセスオブジェクトを保持できる。
グループに属する全プロセスを1つのタップに入れることで、1つのゲインを共有させる。
最初の1つだけをタップすると、音を出しているプロセスを取り逃す。

## 永続化のキー

`AudioObjectID` も PID もプロセス再起動で変わる。設定の永続化には
グループ化キー(所有アプリのバンドル ID)を使う。
